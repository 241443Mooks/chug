# Writing for this repository

Use plain UK English in the owner's voice: direct, thoughtful and specific. Say what the tool does and where it falls short. Do not write a sales pitch or imitate personal warmth with a sign-off.

- Use “Chug” as the existing application name. Do not expand it into an acronym or add a slogan.
- Keep documentation short. README explains the tool and its boundaries; START_HERE explains how to run it. Link to details rather than repeat them.
- Distinguish what works now, what is planned, what is unverified and what the system must never decide. Keep public demo and local app claims separate.
- Prefer “compares documents” to claims about transforming work, empowering teams or creating an enduring foundation. Avoid corporate language, inflated adjectives and repeated statements of intent.
- Do not claim legal accuracy, time savings, production security, live AI results or owner acceptance without evidence.
- Keep exact commands, API names, hashes, test evidence, licence terms and source documents intact. Remove promotional explanation without removing technical limits or useful reproduction steps.
- Treat dated test reports and decision records as history. Add a clearly dated correction when needed; do not rewrite previous failures as successes.

The tool can compare and organise evidence. People decide applicability, accept legal risk and approve guidance. This boundary is not a feature waiting to be automated.
