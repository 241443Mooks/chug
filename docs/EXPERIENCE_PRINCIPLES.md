# Review experience

## Required journeys

- **Queue:** see which documents need attention and why.
- **Routine candidate:** see the checks and differences before making a human decision. Routine is not approved.
- **Changed wording:** inspect incoming and reference passages together, then record an assessment.
- **Flagged exception:** reach the exact evidence even when most of the document is unchanged.
- **Incomplete analysis:** see what could not be checked and open the original for manual review.
- **Past decision:** inspect its source, conditions and status before deciding whether it applies.

## Interface rules

Lead with findings; keep detailed checks available. Use consistent labels, readable layouts, keyboard access and clear focus states. Distinguish a suggestion from a human decision. Keep failed, empty and loading states understandable.

A finding link must open that finding. A save action must show whether it succeeded. Public examples must not look as though they save decisions.

Check the rendered workflow on desktop and a narrow screen. Automated UI checks alone do not establish usability or accessibility. Record observed gaps in the [review checklist](CREATIVE_REVIEW.md).
